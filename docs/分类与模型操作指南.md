# 分类与模型操作指南

> 架构前提：分类 Tab 和模型列表都从数据库注册表渲染（Model / Category 表），**改类目不需要动前端代码**。
> 唯一真相源：`scripts/seed-model-config.mjs` 里的配置（已进 git 版本管理）。

## 场景 1：调整 / 新增某模型的分类 Tab

例：把「UI与界面」从「更多」拆成独立 Tab。

1. 编辑 `scripts/seed-model-config.mjs` 的 `CATEGORIES` 配置：
   - 从「更多」的 `rawAliases` 里移除 `"🧩 UI与界面"`
   - 新增 `{ name: "UI界面", sortOrder: 7, rawAliases: ["🧩 UI与界面"] }`
2. 重跑种子（幂等）：
   ```bash
   node scripts/seed-model-config.mjs
   ```
3. 重跑导入（按新映射刷新所有案例的 displayCategory）：
   ```bash
   node scripts/import-cases.mjs
   ```

完成。`sortOrder` 控制排序，`rawAliases` 控制原始分类到展示分类的归属。

⚠️ **重命名分类的坑**：种子按 `modelId + name` upsert，改名会新增一行而旧行残留（出现空 Tab）。处理：删除旧行（Prisma Studio 或 SQL），或把种子升级为「完全同步」模式。

## 场景 2：接入全新模型体系（如 Nano Banana）

1. `seed-model-config.mjs` 中新增模型块（Model 行 + 该模型的 CATEGORIES 组）
2. 数据文件 `data/cases-<model>.json`（字段：num/title/category/source/image/prompt）
3. 执行：
   ```bash
   node scripts/seed-model-config.mjs
   node scripts/import-cases.mjs
   node scripts/localize-image-paths.mjs <public下的图片目录>
   ```

说明：URL 参数 `?model=<id>` 已支持；网站端的模型切换 Tab UI 属于 Phase B（见 `docs/plans/2026-09-13-multi-model-design.md` §9）。

## 场景 3：临时快速调整

`npx prisma studio` 可视化改 Model / Category 表。**注意：不进 git**，改完必须回填种子脚本，否则重跑种子时被覆盖。

## 案例 Description 的维护

- 541 条人工描述存于 `data/case-descriptions.json`（num → 文案），导入时自动合并
- 改描述 = 改这个 JSON → 重跑 `import-cases.mjs`
- 新增案例没有描述时自动回落 `Model.descriptionTpl` 模板

## 完整重建（换机 / 数据库坏了）

```bash
npm install
npx prisma generate
npx prisma db push          # 建表
node scripts/seed-model-config.mjs
node scripts/import-cases.mjs
node scripts/localize-image-paths.mjs
# 图片如缺失：node scripts/download-images.mjs（仅上游原始图）
```
